Before integrating, prepare the following:

- A Billions API key stored only on your backend.
- A public HTTPS callback endpoint.
- A unique order reference in your system.
- A persistent place to store the Billions invoice ID.
- A strategy for retrying network requests safely.

<Note>
  The SDKs use `https://api.billions.works` and public API version `v1` by
  default. Use `https://api-sandbox.billions.works` while testing.
</Note>

## Choose an environment

| Environment | Base URL | Use it for |
| --- | --- | --- |
| Sandbox | `https://api-sandbox.billions.works` | Integration development and testing |
| Production | `https://api.billions.works` | Live payments and money operations |

Keep separate credentials and configuration for each environment. Make the API
base URL an environment variable so production cannot be selected accidentally:

```bash
BILLIONS_API_URL=https://api-sandbox.billions.works
BILLIONS_API_KEY=your-sandbox-api-key
```

## Keep credentials server-side

Never embed the API key in browser code, a mobile application, a public
repository, or logs. Load it from a secret manager or environment variable.

For signed money operations and optional webhook signature verification, also
store the original API key secret. It is displayed only once when the API key
is created and must be treated as a server-side secret.

```bash
BILLIONS_API_SECRET=your-api-key-secret
```

## Define two identifiers

Use separate identifiers for separate jobs:

| Field | Purpose | Recommendation |
| --- | --- | --- |
| `order_no` | Connects the invoice to your business order | Use your stable internal order number |
| `idempotencyKey` | Makes a create attempt safe to retry | Derive it from the order and payment attempt |

An order may have more than one payment attempt. In that case, keep `order_no`
stable and use a new idempotency key for each intentional attempt.

<Warning>
  Reuse an idempotency key only when retrying the same logical invoice creation.
  Do not reuse one key for unrelated orders.
</Warning>

Use the [public currencies endpoint](/api/overview#discover-the-api) instead of
hard-coding a currency list.
