The compatibility API lets an existing Cryptomus payment integration create
Billions invoices with limited changes to its configuration. Use this path if
your application or store already has a Cryptomus SDK or module. For a new
integration, use the [Billions Public API](/api/overview) or an
[official Billions SDK](/sdks/overview).

## Connect an existing integration

<Steps>
  <Step title="Create a Billions API key">
    In your Billions account settings, create an API key and save both values
    returned when it is issued: `apiKey` and `secretKey`. The secret is shown
    only once. Keep it on your server.
  </Step>
  <Step title="Change the API base URL">
    Replace the Cryptomus API base URL inside the SDK or module with
    `https://compatibility-cm.billions.works`. Keep the module's `/v1/...`
    endpoint paths. If its configuration contains a full URL ending in `/v1`,
    use `https://compatibility-cm.billions.works/v1` instead.
  </Step>
  <Step title="Enter the matching credentials">
    Set the module's Merchant UUID and payment secret to the values from the
    **same** Billions API key, following the mapping below.
  </Step>
  <Step title="Run a test payment">
    Create an invoice, open its returned payment URL, and confirm that the
    module receives a status update. Check the module's behavior for the
    operations it uses before enabling live checkout.
  </Step>
</Steps>

| Cryptomus field | Billions value |
| --- | --- |
| Merchant UUID | `apiKey` — the API key UUID, not the Billions merchant's internal ID |
| Payment API Key / Secret | `secretKey` issued together with that `apiKey` |

The payment secret is used to sign requests and callbacks. Older Billions API
keys without a signing secret must be reissued. Keep the secret out of browser
code, URLs, and logs.

<Note>
  Change the URL used for **API requests**. Keep the checkout URL returned in
  the invoice response and your own callback URL as they are; the module should
  use the returned checkout URL without rewriting its host.
</Note>

## SDKs and modules

The [Cryptomus PHP SDK](https://github.com/CryptomusCom/api-php-sdk) can use
this API for the supported payment methods when its API base URL is changed.
The community TypeScript package
[`cryptomus-js`](https://github.com/0xJord4n/cryptomus-js) has also been used
with the compatibility host by overriding its payment client's `baseUrl`;
that package does not expose a stable base URL option, so check this override
when updating it.

The [Cryptomus module catalog](https://doc.cryptomus.com/sdks-and-modules/modules)
lists modules for these platforms. They can be considered for this compatibility
path when their API URL can be changed and their checkout uses the supported
payment methods:

- **Stores:** WooCommerce, PrestaShop, OpenCart, Magento, BigCommerce, CS-Cart,
  PHPShop, Easy Digital Downloads, Webasyst, VirtueMart.
- **Billing and hosting:** WHMCS, BillManager, RootPanel, Clientexec, HostBill,
  Blesta, WISECP, Amember.
- **Other platforms:** XenForo, Tilda, Azuriom, Invision Community, Watbot.

Module versions and the methods they call vary. This list identifies the
available Cryptomus modules, **not** a guarantee that every module and feature
works unchanged. In particular, modules that require static wallets, refunds,
mark-as-paid, or webhook resend need additional support beyond the current
compatibility API. For WooCommerce, you can alternatively use the
[official Billions plugin](/store-integrations/woocommerce). For BILLmanager 6,
see the [official Billions module](/store-integrations/billmanager). For a Tilda
internal test, see the [Billions Custom Payment Gateway setup](/store-integrations/tilda).

## Supported payment operations

| Method | Path | Use |
| --- | --- | --- |
| `POST` | `/v1/payment` | Create an invoice |
| `POST` | `/v1/payment/info` | Retrieve an invoice by `uuid` or `order_id` |
| `POST` | `/v1/payment/list` | List compatible invoices |
| `POST` | `/v1/payment/services` | List available payment currencies and networks |
| `POST` | `/v1/payment/qr` | Get a QR image for an invoice with a payment address |

These endpoints use Cryptomus-style `merchant` and `sign` headers. The `sign`
value is the lowercase MD5 hex digest of the Base64-encoded **exact JSON body
bytes** followed by `secretKey`. It differs from the RFC 8785/HMAC signature
used by [Billions signed money operations](/api/request-signing). Existing
Cryptomus SDKs and modules usually calculate this signature themselves.

Invoices created here send Cryptomus-style callbacks to `url_callback` when
provided. Their `sign` is in the JSON body, and their format differs from
[Billions-native webhooks](/integration/callbacks-and-security). Verify and
process them according to the module's callback flow.

This is a partial payment API compatibility layer. Refunds, static wallets,
mark-as-paid, webhook resend, and payout methods are not implemented in this
API. Unsupported request options are rejected explicitly.
