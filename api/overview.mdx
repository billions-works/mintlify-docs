Billions Public API v1 is available in separate sandbox and production
environments.

| Environment | Base URL |
| --- | --- |
| Sandbox | `https://api-sandbox.billions.works` |
| Production | `https://api.billions.works` |

Use sandbox for development, automated tests, and integration verification.
Move to the production base URL only after completing the go-live checklist.
For a guided check of invoice creation, redirect, and callbacks, see
[Test in sandbox](/integration/sandbox-testing).

## Authentication levels

Most merchant endpoints require the API key in a request header:

```text
x-api-key: <merchant API key>
```

Endpoints that can move funds require both the API key and an HMAC signature
created with the API key secret. See [Request signing](/api/request-signing).

| Authentication | Endpoints |
| --- | --- |
| None | Version, currencies, countries |
| API key | Merchant profile, invoice creation, fee estimation, invoice retrieval |
| API key + signed request | Withdrawal creation, crypto refunds, fiat refunds |

## Endpoints

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/public/v1/version` | Return the public API version |
| `GET` | `/public/v1/currencies` | List currently supported currencies and their metadata |
| `GET` | `/public/v1/countries` | List supported countries |
| `GET` | `/public/v1/me` | Return the merchant associated with the API key |
| `POST` | `/public/v1/invoices/create` | Create an invoice |
| `POST` | `/public/v1/invoices/estimateFees` | Estimate invoice fees |
| `GET` | `/public/v1/invoices/{id}` | Retrieve the current invoice by Billions ID |
| `GET` | `/public/v1/invoices/byOrder/{order_no}` | Retrieve invoices by your order reference |
| `POST` | `/public/v1/withdrawals/create` | Create a signed withdrawal request |
| `POST` | `/public/v1/refunds/refundCrypto` | Create a signed crypto refund request |
| `POST` | `/public/v1/refunds/refundFiat` | Create a signed fiat refund request |

See [Create an invoice API](/api/create-invoice) for a field-by-field request
reference and the response fields used for payment verification.

## Discover the API

Use the OpenAPI specification for the environment you are calling to inspect
its currently deployed request and response schemas. During a staged rollout,
an endpoint may appear in one environment before another:

- Sandbox Swagger UI:
  [`https://api-sandbox.billions.works/public/v1/docs`](https://api-sandbox.billions.works/public/v1/docs)
- Sandbox OpenAPI JSON:
  [`https://api-sandbox.billions.works/public/v1/swagger.json`](https://api-sandbox.billions.works/public/v1/swagger.json)
- Production Swagger UI:
  [`https://api.billions.works/public/v1/docs`](https://api.billions.works/public/v1/docs)
- Production OpenAPI JSON:
  [`https://api.billions.works/public/v1/swagger.json`](https://api.billions.works/public/v1/swagger.json)

The **Live production schema** entry in this documentation is generated from the
hosted production OpenAPI URL when Mintlify publishes the docs. This avoids
copying the schema into this repository, but backend-only changes do not
automatically trigger a Mintlify deployment: publish the docs again after
updating the backend to refresh the generated page.
The current production OpenAPI document does **not** provide per-field
descriptions for invoice creation; the explanations in
[Create an invoice API](/api/create-invoice) are maintained here until those
descriptions are added to the backend schema.
The generated endpoint is shown without an interactive request sender because
the source schema advertises a relative server URL.

## Rate limits and network allowlists

No numeric Public API rate limit or guaranteed callback source-IP range is
published here. Do not build against an assumed requests-per-minute limit or
hard-code an IP list found in an old response. Handle `429` and transient
errors with bounded backoff, honor `Retry-After` when present, and preserve
idempotency keys across retries. If your firewall requires a fixed callback
source range, ask Billions support for the current operational guidance.

<Warning>
  Keep API keys and API key secrets on your backend. Never expose them in a
  browser bundle, mobile application, URL, callback payload, or log.
</Warning>
